# Contributing to this marketplace

## The easy way (recommended)

Install the `plugin-development` plugin, then just say what you want in
plain language from inside a Claude Code session:

- *"Create a new plugin for X"*
- *"Add this skill to the marketplace"*
- *"What plugins exist for observability?"*
- *"Validate the marketplace"*
- *"Publish these changes"*

You don't need to remember the folder layout or JSON schema — the
`plugin-authoring` skill handles scaffolding, versioning, validation, and
committing for you. See
`plugins/plugin-development/skills/plugin-authoring/SKILL.md` if you want to
see exactly what it does.

## The manual way

If you'd rather do it by hand:

### Adding to an existing plugin

1. Drop your skill/command/agent/hook into the right subfolder under
   `plugins/<name>/`.
2. Bump `version` in `plugins/<name>/.claude-plugin/plugin.json`.
3. Run `python3 plugins/plugin-development/scripts/validate.py` from the
   repo root and fix anything it flags (or run `/validate-plugin` from
   Claude Code, which fixes the mechanical stuff automatically).
4. Commit and push. `docs/CATALOG.md` will have been regenerated by the
   validator — include it in your commit.

### Creating a new plugin

1. Create `plugins/<your-tech>/` with a `.claude-plugin/plugin.json`
   (`name`, `version: "0.1.0"`, `description`, `author`), plus whichever of
   `skills/`, `commands/`, `agents/`, `hooks/`, `.mcp.json` it needs.
2. Add an entry to the root `.claude-plugin/marketplace.json` — `name`,
   `source`, `description`, `version`, `category`, `tags`, `owner`. Reuse an
   existing `category` where it fits so browsing stays coherent.
3. Run `python3 plugins/plugin-development/scripts/validate.py` (or
   `/validate-plugin`), fix anything flagged, commit, push.

## Conventions

- **One technology per plugin.** Don't create a plugin per skill, and don't
  bundle unrelated technologies into one plugin.
- **`docs/CATALOG.md` is generated. Never hand-edit it.** It's rebuilt from
  `marketplace.json` every time the validator runs clean.
- **Always run the validator before pushing.** There's no CI here — the
  validator is the only safety net, so don't skip it.
- **Every skill needs a specific `description`.** Claude decides whether to
  load a skill based only on that text — vague descriptions mean it silently
  never triggers. Say what it does and when to use it, concretely.

## Ownership

Every plugin entry in `marketplace.json` should have an `owner` field. If
you create a plugin, you're the default owner — that's who teammates should
ping when something in it breaks or needs updating. Keep it current if
ownership changes.
